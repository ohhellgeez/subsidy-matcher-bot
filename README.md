# Навигатор по мерам поддержки (subsidy-matcher-bot)

Чат-бот для платформы **МАХ**, который подбирает предпринимателям, фермерам и
самозанятым доступные субсидии, гранты и льготы со ссылками на оформление.
Подбор выполняется автоматически по **ИНН** или по короткой **анкете** из 3–4 вопросов
(регион, форма бизнеса, отрасль, наличие сотрудников).

> Направление хакатона: «Навигация по мерам поддержки для бизнеса и АПК».

---

## 1. Назначение решения

Снизить порог получения государственной поддержки для малого и среднего бизнеса,
фермеров и самозанятых. Вместо ручного поиска по десяткам сайтов и реестров
пользователь в одном диалоге получает персональный список актуальных мер
(субсидий, грантов, льготных займов) с суммой, сроком подачи, категорией получателей
и прямой ссылкой на оформление.

## 2. Основной пользовательский сценарий

1. Пользователь открывает чат-бота в МАХ и нажимает **«Начать»** (или отправляет `/start`).
2. Бот просит **ИНН**:
   - если ИНН найден в базе — данные компании подставляются автоматически;
   - если ИНН не найден — бот предлагает ввести его ещё раз или перейти к анкете;
   - кнопка **«Подобрать по анкете»** запускает ручной ввод.
3. При ручном вводе бот задаёт до 4 вопросов: регион → форма бизнеса → отрасль → наличие сотрудников.
4. Бот сопоставляет профиль с мерами поддержки и выводит итог: **«Найдено мер: N»**.
5. Пользователь нажимает **«Показать результаты»** и видит рейтинговый список (до 5 мер).
6. По кнопке **«Изучить меру»** открывается карточка меры: описание, сумма, срок подачи, категория получателей, ссылка.
7. Кнопка **«Открыть ссылку»** ведёт на страницу оформления; после — можно вернуться к списку,
   **«Изменить параметры»** или **«Скачать подборку»** (текстовая выгрузка всех найденных мер).
8. В любой момент доступны кнопки **«← Назад»** и **«Начать заново»**.

## 3. Состав решения

| Компонент | Технология | Назначение |
| --- | --- | --- |
| `bot` (Python) | Python 3.11 | Основное приложение: коннектор API МАХ, FSM диалога, скоринг, подбор мер |
| `db` | PostgreSQL 15 | Хранение мер поддержки, требований, регионов, компаний |

| Миграции | Alembic | Создание/обновление схемы БД |

## 4. Архитектура

```
                       +-------------------------------+
  Платформа МАХ         |  Бот (Python, src/)          |
  (platform-api2.max.ru)|                               |
      |                 |  max_client/  — HTTP-коннектор|
      |  Update         |  handlers.py   — диспетчер    |
      +---------------->|  bot/          — FSM, скоринг |
  polling / webhook     |  config.py     — конфиг (.env)|
      ^                 |  main.py       — точка входа  |
      |  send/answer    |  webhook.py    — FastAPI-сервер|
      +-----------------+                               |
                        +-------------+-----------------+
                                      |
                        +-------------+-------------+
                        |             |             |
                     PostgreSQL      Redis      Webhook :8000
                     (меры,        (сессии)    (только webhook-режим)
                      профили)
```

**Модули:**

- `src/max_client/` — HTTP-клиент API МАХ (`client.py`), модели (`models.py`), ошибки (`errors.py`).
- `src/handlers.py` — диспетчер входящих событий (`bot_started`, `message_created`, `message_callback`).
- `src/bot/` — доменная логика:
  - `dispatcher.py` — конечный автомат диалога (переходы и рендер);
  - `steps.py` — вопросы анкеты; `catalog.py` — справочники (ОПФ, отрасли, регионы);
  - `matcher.py` — сопоставление профиля с мерами и скоринг;
  - `storage.py` — хранилище сессий (Redis с fallback в память);
  - `validators.py` — валидация ИНН, имён, поиск по ИНН;
  - `render.py` — тексты ответов и клавиатуры.
- `src/config.py` — загрузка настроек из переменных окружения.
- `src/main.py` — точка входа (выбор режима polling/webhook).
- `src/webhook.py` — FastAPI-приложение (endpoint `/webhook`, healthcheck `/health`).
- `database/models.py` — SQLAlchemy-модели; `database/seed.py` — загрузка фикстур.
- `migrations/` — Alembic-миграции.

## 6. Внешние сервисы и интеграции

| Сервис | Назначение | Как проверяется |
| --- | --- | --- |

## 7. Работа с данными

- **PostgreSQL** хранит справочные и бизнес-данные (см. `database/models.py`):
  - `support_measures` — меры поддержки (включая официальные источники `source_name`, прямые ссылки `source_url`, суммы, сроки действия и подробные описания получателей `recipient_description`);
  - `measure_requirements` — строгие системные требования для алгоритма (ОПФ, ОКВЭД, регион/ОКАТО, сотрудники, срок бизнеса);
  - `documents` — документы/ссылки меры;
  - `regions` — регионы (ОКАТО, ISO-код, ФО);
  - `companies` — тестовые компании (ИНН, ОПФ, ОКВЭД, метрики).
- **Redis** хранит сессии диалогов (`session:{user_id}`) с TTL 24 ч; при недоступности Redis бот работает с in-memory fallback.
- **Подбор** (`matcher.py`): профиль (ОПФ, ОКВЭД, ОКАТО, сотрудники, срок бизнеса) сопоставляется с `measure_requirements`; каждая мера получает скоринг-балл (база 100 + бонус за сумму + бонус за близкий дедлайн), результаты сортируются по убыванию. Человекочитаемые данные для UI берутся из `support_measures`.
- Схема создаётся миграциями Alembic (`alembic upgrade head`), наполнение — `database/seed.py`.

Одна команда, поднимающая все локальные компоненты: `docker compose up --build`

## 13. Пошаговый сценарий проверки

1. `cp .env.example .env` и укажите рабочий `MAX_BOT_TOKEN`.
2. `docker compose up --build` — дождитесь `healthy` у `db`/`redis` и запуска бота.
3. В МАХ откройте диалог с ботом и нажмите **«Начать»**.
4. Пройдите сценарий по ИНН: введите `7736050003` → бот автоматически подставит
   «ООО Инновации Плюс» и выдаст итог.
5. Нажмите **«Показать результаты»** → **«Изучить меру»** → проверьте карточку меры и ссылку.
6. Вернитесь (**«Ещё меры»**) и нажмите **«Изменить параметры»** — измените, например, регион.
7. Проверьте сценарий по анкете: **«Подобрать по анкете»** → регион → форма бизнеса → отрасль → сотрудники.
8. Проверьте обработку ошибок: введите несуществующий ИНН (например, `1111111111`) —
   бот должен предложить повторить или перейти к анкете.
9. Проверьте **«Скачать подборку»** и кнопки **«← Назад»** / **«Начать заново»**.

## 15. Известные ограничения

- Подбор работает только по данным, загруженным в БД (демо-набор: 4 региона, 4 компании, 5 мер).
  Для боевого использования нужен полный реестр мер и актуальные справочники.
- Единственный внешний сервис — API МАХ: без действующего токена и доступа к платформе
  бот не сможет принимать/отправлять сообщения.
- Ручная анкета использует упрощённый справочник (3 региона, 5 отраслей) — не все ОКВЭД/регионы.
- Сессии хранятся в Redis 24 ч; при недоступности Redis используется in-memory fallback,
  который не переживает рестарт контейнера.
- «Скачать подборку» формирует текстовое сообщение, а не файл (ограничение формата MVP).

## 17. Контракт API МАХ (краткая шпаргалка)

- **Base URL:** `https://platform-api2.max.ru`; авторизация заголовком `Authorization: <token>`.
- **Отправка:** `POST /messages?user_id={id}` (или `?chat_id={id}`), тело `NewMessageBody`
  (`text`, `attachments`, `notify`, `format`).
- **Кнопки:** `attachments: [{type: "inline_keyboard", payload: {buttons: [[{type,text,payload|url}]]}}]`;
  типы: `callback`, `link`, `message`, `clipboard`, `request_contact`, `request_geo_location`, `open_app`.
- **Callback:** `POST /answers?callback_id={id}`; событие `message_callback` содержит объект `callback`
  (`callback_id`, `payload`, `user`).
- **Получение событий (взаимоисключающие режимы):**
  - Long Polling — `GET /updates?marker=&limit=&timeout=&types=` → `{updates: Update[], marker}`.
  - Webhook — `POST /subscriptions` (`url`, `update_types`, `secret`); события приходят HTTPS POST
    с заголовком `X-Max-Bot-Api-Secret`.
- **Ограничения:** 30 rps на API; не более 2 сообщений/сек в один диалог.
- **События:** `bot_started`, `bot_added`, `message_created`, `message_callback`, `message_edited`,
  `message_removed`, `comment_*`, `user_added/removed` и др.

Полная документация: <https://dev.max.ru/docs-api>.

## 18. Сертификаты Минцифры (TLS)

API МАХ использует сертификаты **Минцифры России** (`Russian Trusted Root CA` /
`Russian Trusted Sub CA`), которых нет в стандартном CA-бандле. Поэтому:

- **В Docker** — решается автоматически: `Dockerfile` добавляет `certs/mincifry_ca.pem` в CA-бандл `certifi`.
- **Локально (без Docker)** — укажите бандл в `.env`: `MAX_CA_BUNDLE=./certs/mincifry_ca.pem`.

Сертификаты лежат в `certs/` (получены из цепочки `platform-api2.max.ru` и официального
CDP Минцифры `nuc-cdp.digital.gov.ru`).
